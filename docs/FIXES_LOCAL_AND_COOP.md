## 1. «Локальная игра не работает — нет соединения с сервером»

**Причина.** Режим **LOCAL (📡 ЛОКАЛЬНАЯ ИГРА)** подключался к `ws://<hostname>:3000`,
но на этом адресе **ничего не слушало** — relay-сервер нужно было запускать вручную
(`npm start` в папке сервера). В Electron-сборке этого никто не делал, поэтому
появлялась ошибка «нет соединения с сервером».

**Решение.**
- Добавлен **встроенный relay-сервер без внешних зависимостей**: `Game/local-server.js`.
  Реализует тот же протокол, что и `Byte Blaster Server/server.js`, но на чистых
  встроенных модулях Node (`http` + `crypto`) — поэтому пакуется внутрь приложения
  и не требует `node_modules`.
- `main.js` запускает его **автоматически при старте** на `0.0.0.0:3000`
  (`startEmbeddedRelay()`), так что `ws://localhost:3000` всегда отвечает.
  Если порт занят (другое окно игры / уже запущенный сервер) — ошибка `EADDRINUSE`
  гасится, LOCAL продолжает работать.
- Для игры **между разными машинами** в одной сети добавлено поле
  **«АДРЕС ХОСТА (LAN)»** на экране поиска комнат (показывается только в режиме
  LOCAL). Гость вводит IP хоста (например `192.168.1.5`), хост видит свои IP
  (через `electronAPI.getLanInfo()` → `net:lanInfo` в `main.js`). Адрес сохраняется
  в `localStorage` (`bb_net_lanhost`).

**Файлы:** `Game/local-server.js` (новый), `main.js`, `preload.js`,
`assets/network.js`, `index.html`, `localisation/*.json` (ключи `netLanHostLabel`,
`netLanHostPlaceholder`, `netLanYourIp`, `netLanNoIp`).

## 2. У гостей (не-хост) огонь/лёд/бластер не сбрасывались при контакте с врагами

**Причина.** Архитектура host-authoritative: вся логика босса (включая
**столкновение игрока с боссом**, которое и снимает усиление) живёт в `updateBoss()`,
а у гостей `updateBoss()` **полностью отключена** (`if(netActive && !netIsHost) return;`).
Поэтому гость мог стоять в боссе без последствий — стадия робота не понижалась,
огонь/лёд/бластер не сбрасывались. (Контакт с **обычными** врагами у гостей
обрабатывается в `updatePlayer()`, которая выполняется у всех, и работал корректно.)

**Решение.** Контакт игрок↔босс теперь определяется **на каждом клиенте**:
- Добавлена функция `_bossPlayerContact()` — повторяет логику столкновения из
  `updateBoss()` (стомп / урон / снятие усиления).
- Гостевая ветка `updateBoss()` теперь вызывает `_bossPlayerContact()` вместо
  простого `return`. ИИ босса (движение/стрельба/hp) остаётся за хостом; гость
  лишь обрабатывает касание.
- `damageBoss()` у гостей уже перенаправляется хосту (через `network.js`),
  а `boss_sync` перетирает любое локальное состояние — рассинхрона нет.

**Файлы:** `assets/game.js` (`_bossPlayerContact`, ветка в `updateBoss`).

## 4. Проверки и тесты сетевой игры

Добавлен тестовый стенд `Game/_nettest/relay.test.js` (исключён из сборки в
`package.json → build.files`). Он поднимает встроенный relay и гоняет настоящие
WebSocket-клиенты (библиотека `ws`, маскированные кадры — как в браузере),
проверяя:

1. рукопожатие WebSocket и приветствие `connected{id,maxPlayers}`;
2. `create_room` (код из 6 безопасных символов, хост в списке);
3. `join_room` + рассылку `player_joined`;
4. `set_color` → `color_changed`;
5. `set_ready` → `ready_changed`;
6. `start_game` только хостом (`not_host` для гостя), общий seed/level;
7. ретрансляцию `game_state` → `player_state` (включая поля усилений);
8. авторитет хоста для `enemies_sync` (200 врагов — проверка 16-битной длины кадра;
   sync от гостя игнорируется);
9. `game_event`, санитайзинг `chat`, `ping`→`pong`;
10. `list_rooms` (публичная комната видна);
11. `invalid_json`;
12. `room_full` (лимит комнаты);
13. failover хоста: при выходе хоста гость получает `promoted_to_host`;
14. `room_not_found`.

**Результат: 25/25 passed.** Запуск: `cd Game/_nettest && npm i && node relay.test.js`.

# Доработки ко-опа (вторая итерация)

Дата: 2026-06-20

## 5. Чекпоинт перекрашивается в цвет игрока (синхронно по сети)

Локально чекпоинт уже красился в цвет коснувшегося игрока. Теперь это
**синхронизируется**: когда любой игрок берёт чекпоинт, его клиент шлёт
`game_event{event:'checkpoint', data:{idx, color}}`, и на всех экранах чекпоинт
перекрашивается в цвет того, кто его взял (одинаково у всех).

**Файлы:** `assets/game.js` (`touchCheckpoints`), `assets/network.js`
(обработчик `checkpoint` в `handleRemoteEvent`).

## 6. Ожидание игроков перед переходом на следующий уровень

Раньше уровень переключался, как только **любой** игрок добегал до флага.
Теперь:
- Игрок, прошедший уровень, **замирает** у флага (неуязвим), экран **затемняется**
  и показывается «**Ожидание игроков X/N**» (оверлей `#netWaiting`).
- Хост ведёт подсчёт финишировавших (`_netFinished`) и **рассылает прогресс**
  (`finish_progress`) — у всех обновляется счётчик X/N.
- Уровень переключается **только когда все** дошли до флага: хост шлёт
  `level_complete` (или `won` на финальном уровне), и все вместе уходят на
  следующий уровень через обратный отсчёт.
- Важно: завершивший игрок **не** уходит в одиночный `levelclear`, поэтому
  у **хоста продолжает считаться ИИ врагов/босса** для тех, кто ещё на уровне
  (никаких «замираний» мира).
- Отвалившийся игрок исключается из подсчёта, чтобы не блокировать комнату.

**Файлы:** `assets/game.js` (`doFlagComplete` переписан, `_persistAdvProgress`,
заморозка в `updatePlayer`), `assets/network.js` (`netReportFinish`,
`_hostMarkFinished`, `_hostBroadcastProgress`, `_hostAdvanceRoom`,
`showNetWaiting/hideNetWaiting`, `_resetFinishState`, обработчики
`finish/finish_progress/won`), `index.html` (`#netWaiting`),
`localisation/*.json` (`netWaitingPlayers/Title/Sub`).

## 7. Скрытие запущенных комнат + старт только когда все «готовы»

- `list_rooms` больше **не показывает комнаты с уже запущенной игрой**
  (`!room.inGame`).
- Хост может нажать «Старт» **только когда все остальные игроки нажали
  «ГОТОВ»** — теперь это проверяется не только в UI, но и **на сервере**
  (`not_all_ready`), так что обойти нельзя.

**Файлы:** `Game/local-server.js`, `Byte Blaster Server/server.js`
(фильтр `list_rooms` + проверка готовности в `start_game`),
`assets/network.js` (обработка ошибки `not_all_ready`),
`localisation/*.json` (`netErrNotAllReady`).
