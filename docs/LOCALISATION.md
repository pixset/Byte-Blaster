# 🌍 Локализация

**50 языков × 982 ключа, покрытие 100%.** Ни одного пропуска, ни одной сбитой
подстановки, ни одной захардкоженной строки в коде.

---

## 1. Как это работает

Каждый язык — один JSON-файл `assets/localisation/<код>.json`, плоский словарь
`ключ → строка`. Эталон — `en.json`: он задаёт, какие ключи вообще существуют.

```json
{
  "levelClear": "LEVEL {0} COMPLETE!",
  "infDesc": "endless maps<br>rising difficulty<br>beat the clock"
}
```

- `{0}`, `{1}` — подстановки, порядок должен совпадать с английским.
- HTML (`<br>`, `<b>`, `<span>`) допустим в строках, которые вставляются через
  `innerHTML` — набор тегов тоже должен совпадать с оригиналом.

### Из JavaScript

```js
t('levelClear', level)          // "УРОВЕНЬ 5 ПРОЙДЕН!"
```

Ключ, которого нет в текущем языке, откатывается на английский. Ключа нет
нигде — вернётся сам ключ, и это сразу видно на экране (именно так нашли
пропавшую строку `keys`: в HUD уровней-лабиринтов вместо «КЛЮЧИ» показывалось
слово `keys`).

### Из HTML

```html
<button data-i18n="save">SAVE</button>
<div data-i18n-html="advDesc">…</div>
<input data-i18n-ph="netNickPlaceholder">
```

| Атрибут | Куда пишет |
|---|---|
| `data-i18n` | `textContent` |
| `data-i18n-html` | `innerHTML` (для строк с `<br>`) |
| `data-i18n-ph` | `placeholder` |

Текст внутри тега в разметке — только заглушка для верстальщика: при загрузке он
затирается переводом.

### Загрузка

| Платформа | Механизм |
|---|---|
| Electron | IPC `locale:list` / `locale:read` — работает под `file://`, где `fetch` запрещён |
| Web / Android | `fetch("assets/localisation/index.json")`, затем каждый файл |

`index.json` — манифест со списком кодов. **Добавил язык — допиши его туда.**

Тонкость: при `npm run build:html` манифест **регенерируется автоматически** из
того, что реально лежит в каталоге, поэтому собранная веб-версия языки не
потеряет. А вот запуск из исходников (`index.html` с локального сервера, dev-
режим) читает манифест как есть — и язык, забытый в `index.json`, не появится
только там. Electron не зависит от манифеста вообще: он читает каталог напрямую.

Именно так и вышло с десятью языками, добавленными последними: файлы лежали,
Electron их показывал, в собранной веб-версии они были, а в исходном
`index.json` их не было. Расхождение чинится одной командой:

```bash
node -e "const fs=require('fs');const d='assets/localisation';fs.writeFileSync(d+'/index.json',JSON.stringify(fs.readdirSync(d).filter(f=>f.endsWith('.json')&&!f.startsWith('_')&&f!=='index.json').map(f=>f.slice(0,-5)).sort())+'\n')"
```

## 3. Аудит — `tools/loc-audit.js`

Расхождения накапливались молча: разработчик добавлял ключ в `en.json` и
`ru.json`, остальные файлы отставали, `t()` откатывался на английский, и в игре
ничего не «ломалось» — просто половина интерфейса тихо становилась английской.
Инструмент делает эту тишину видимой.

```bash
node tools/loc-audit.js                # сводная таблица по всем языкам
node tools/loc-audit.js de             # детальный отчёт по одному языку
node tools/loc-audit.js --keys         # ключи в коде vs ключи в en.json
node tools/loc-audit.js --untranslated  # все английские остатки
```

Пять проверок:

| Колонка | Что значит |
|---|---|
| `missing` | ключ есть в `en.json`, но нет в языке |
| `stale` | ключ есть в языке, но его больше нет в `en.json` |
| `{n}` | набор подстановок не совпадает с английским |
| `<tag>` | набор HTML-тегов не совпадает |
| `english` | строка дословно равна английской |

**Целевое состояние — нули во всех пяти колонках у всех языков.** Оно
достигнуто; любое ненулевое число означает регресс.

`--keys` ловит вторую категорию проблем: ключи, которые код запрашивает, но
никто не определил (сейчас 0), и ключи, определённые, но не используемые
(накопившийся мусор, безвредный, но его стоит однажды вычистить).

## 3a. Ключи из кода — `tools/loc-keys-used.js`

Отдельная проверка того же свойства с другой стороны: собирает всё, что игра
запрашивает, и сверяет со словарём.

```bash
node tools/loc-keys-used.js
```

Ключи берутся тремя способами, все три и собираются:

| Как записано | Где встречается |
|---|---|
| `t('key')` | код игры |
| `T('key', 'запасной текст')` | экран «Что нового» |
| `data-i18n="key"` | разметка `index.html` |

Склейки вида `T('bossHint' + wi)` известны только во время работы: они
перечисляются отдельно как «проверьте вручную», а не считаются ошибкой.
Литералом считается строка, **за которой не идёт `+`** — иначе начало склейки
принималось бы за целый ключ.

Пропущенный ключ нигде не падает: `t()` возвращает само имя, и игрок видит на
экране `dailyNoServer` вместо текста. Ловится только глазами — или этим
скриптом.

## 3b. Слияние партий — `tools/loc-merge.js`

Править полсотни JSON-файлов руками — верный способ где-нибудь сбить запятую и
уронить разбор у всей игры. Скрипт принимает один файл с переводами и
раскладывает их по языкам.

```bash
node tools/loc-merge.js batch.json              # влить
node tools/loc-merge.js batch.json --dry        # посмотреть, ничего не записывая
node tools/loc-merge.js batch.json --overwrite  # перезаписать существующее
```

Формат файла:

```json
{
  "de": { "dailyTitle": "TAGESLEVEL", "ghostOff": "🚫 Aus" },
  "fr": { "dailyTitle": "NIVEAU DU JOUR", "ghostOff": "🚫 Désactivé" }
}
```

Порядок ключей берётся из `en.json`, поэтому все файлы остаются в одном порядке
и их можно сравнивать построчно. Уже существующий перевод по умолчанию **не
трогается** — случайный повтор партии не затрёт вычитанную строку.

Если в партии окажется ключ, которого нет в `en.json`, скрипт скажет об этом
отдельно: такой ключ аудит посчитает лишним, а игрок увидит сырое имя.

## 4. Ложные срабатывания и baseline заимствований

Колонка `english` сама по себе врёт, потому что смешивает три разные вещи:

1. **Настоящий пропуск** — «Master Volume» в тагальском.
2. **Имя собственное или код** — `UNIT-7`, `LEILA CHEN`, `ARCHON`, `XXXXXX`,
   `192.168.x.x`, `1920 x 1080`. Переводить их было бы ошибкой.
3. **Настоящее заимствование** — «MENU» в малайском, «SABOTEUR» во французском,
   «Later» в нидерландском, «Pause:» в немецком. Английское написание здесь и
   есть правильный перевод.

Первая категория лечится переводом. Вторая — множеством `SAME_BY_DESIGN` внутри
`loc-audit.js` (одинакова для всех языков). Третья не может быть общим списком:
«CHAT» законен в немецком и незаконен в русском. Поэтому она вынесена в
**`tools/loc-loanwords.json`** — baseline вида «язык → список ключей»,
просмотренный вручную один раз, когда покрытие дошло до 100%.

Ключ, которого в baseline нет, по-прежнему попадает в отчёт — то есть новая
рассинхронизация ловится, а старый проверенный шум не мешает.

## 5. Никакого текста в коде — `tools/find-hardcoded.js`

```bash
node tools/find-hardcoded.js
```

Ищет английские литералы, которые пишутся в `floatTxt()`, `textContent` и
`innerHTML`. Типичная находка — не забытый ключ, а **дубль**: строка уже
переведена и используется в одном месте, а в соседнем вызове кто-то написал её
текстом. Именно так русский игрок видел английские всплывашки при полностью
переведённом файле. Сейчас инструмент показывает 0.

## 6. Как добавить язык

1. Скопировать `en.json` → `assets/localisation/<код>.json`, перевести значения.
2. Добавить код в `assets/localisation/index.json`.
3. Добавить флаг и название в `FLAGS` / `LANG_NAMES` в `assets/i18n-new.js`.
4. `node tools/loc-audit.js <код>` — добиться нулей.
5. Запустить игру и переключиться на язык: проверить, что кнопки не разъезжаются
   (немецкий и финский дают самые длинные строки).

## 7. Как добавить строку

1. Ключ и английский текст → `en.json`, русский → `ru.json`.
2. Перевод во **все** остальные файлы (не «потом» — «потом» и есть источник
   расхождений). Партиями по 5–6 языков через `tools/loc-merge.js`.
3. В коде — только `t('ключ')`, никогда текстом.
4. `node tools/loc-audit.js` — нули; `node tools/loc-keys-used.js` — ноль
   пропущенных; `node tools/find-hardcoded.js` — ноль.
5. `npm run sync:www` — иначе веб-версия останется со старыми переводами.

### Что смотреть глазами после большой партии

Аудит проверяет структуру, но не смысл. Отдельно стоит поискать:

* **застрявшие английские слова** внутри нелатинских языков — в ja/ko/zh/th/
  ar/he/hi/bn их видно поиском латиницы. Имена собственные (`Byte Blaster`,
  `NEON RUN`, `Prism Anomaly`) и технические сокращения (`LAN`, `ESC`, `EMP`)
  при этом законны;
* **невидимые символы** — мягкий перенос `U+00AD`, `U+200B`. Исключение —
  RTL-маркер `U+200F` в иврите: он там нужен для правильного вида дефиса;
* **длину коротких подписей**: кнопки и вкладки. Ориентир — самые длинные из уже
  работающих строк того же элемента.

## 7a. Экран «Что нового»

`assets/whatsnew.js` держит тексты **в коде**, парами `[ключ, русский запасной]`,
и тянет перевод через `T()`. Пока перевода нет, показывается русский текст —
поэтому пропуск здесь не заметен по аудиту игры, но заметен игроку.

До сентября 2026 этих 76 ключей не было в словаре вообще: экран истории версий
у всех, включая англоязычных, показывался по-русски. Сейчас переведены все,
включая даты (`wnDate*`) и предрелизный архив (`wnA*`).

Добавляя запись в историю версий, ключ надо завести и в `en.json`, и в `ru.json`,
и во все остальные языки — иначе она молча выпадет в русский.

## 8. Известное ограничение: RTL

Игра **не поддерживает раскладку справа налево** ни для одного языка. Арабский,
иврит, урду и персидский рендерятся слева направо: `dir` не переключается,
интерфейс не зеркалится.

Внутри строки браузер сам применяет bidi-алгоритм, поэтому сами слова
отображаются правильно — неверен порядок элементов и выравнивание панелей. Это
незакрытая задача, а не регресс: так было со дня добавления арабского.
